deepseek-recipe — protocols, not inference

Rust libraries + Python bindings that convert API requests, render DeepSeek prompts, tokenize, and parse model output. The caller must provide model inference, tool execution, and HTTP transport.

Official repo PyPI
Sponsored slot (inactive)

How it stacks with DeepInfer

PieceRole
deepseek-recipeRequest → Conversation → prompt / token IDs; output tokens → protocol responses
DeepInfer (or other backend)Actual model inference on accelerators
Your serviceHTTP, auth, tools, KV/serving glue
Installing recipe alone will not download weights or run V4.1-Flash. Pair it with DeepInfer (offline) or another backend / the official API.

Supported scope (summary)

  • Messages, Chat Completions, Responses — including streaming
  • DeepSeek V4 / V4.1 prompt rendering + attached tokenizer encoding
  • Thinking mode, reasoning effort, temperature, top_p, max tokens defaults
  • Output parsing: reasoning, tool calls, JSON, stop sequences
  • Structured output: json_schema / regex (caller enforces constrained decoding)
  • Images for V4.1 (OpenCV preprocess); V4 replaces images with [Unsupported Image]

Python getting started

Python 3.10+:

python3 -m pip install deepseek-recipe
from deepseek_recipe import ChatCompletionRequest, ConversionOptions, DeepseekV41Encoding

request = ChatCompletionRequest({
    "model": "DeepSeek-V4.1-Flash",
    "messages": [{"role": "user", "content": "Hello"}],
})
converted = request.convert(ConversionOptions())
rendered = DeepseekV41Encoding().render_conversation(converted.conversation)
print(rendered.prompt)

Rust getting started

cargo add deepseek-recipe@0.2 deepseek-recipe-encoding@0.2 serde_json@1

See upstream development guide for source builds and image dependencies.

DeepInfer FAQ

内容对齐 官方 DeepInfer README — 离线推理、算子与服务缺口。

DeepInfer、deepseek-recipe、DeepSeek Harness？

  • DeepInfer — DeepSeek-V4.1-Flash 的开源离线推理引擎（Apache-2.0），定位生产级推理引擎。
  • deepseek-recipe — 协议 / 提示词 / 分词；不执行推理。
  • DeepSeek Harness（DSH） — 智能体运行时 · dshbase.com · 说明。

什么是 DSpark（推测解码）？

DSpark 与置信度调度验证用 draft token 加速解码，并按置信度安排验证。开启：DEEPINFER_ENABLE_MTP_VARLEN=1；DEEPINFER_USE_NEXTN_DECODE 控制最大 draft 长度（默认 5）。

什么是 SWA Bounded Replay？

Decoder 侧 SWA bounded replay 只回放有界后缀，减少 decoder prefill 工作量。README 默认 V4.1：DEEPINFER_YOCO_PREFILL_TRUNCATION_MODE=compact、DEEPINFER_YOCO_PREFILL_KEEP_TOKENS=140。保留后缀须覆盖 SWA 窗口与最大回退长度。

结构化输出？

通过 SamplingParams 的 so_args 约束为 regex、JSON Schema 或 EBNF。见上游 examples/_structured_output.py。

DeepInfer 用哪些算子？

上游列出的优化算子：FlashMLA、DeepGEMM、DeepEP、TileKernels、DeepSelect 与自定义 TileLang，以及 Attention DP / balanced CP、MoE EP + EPLB。

批不变与确定性采样？

批不变推理（DEEPINFER_BATCH_INVARIANT=1，仅 NVIDIA）保证不同 batch 组成下结果一致。确定性采样再配合 DEEPINFER_ENABLE_MTP_VARLEN=0 与固定 seq_seed。

为何缺少 KV cache、Prefill/Decode 分离与负载均衡？

开源版本聚焦离线推理。上游写明完整推理服务仍需：KV cache 系统、VE/Prefill/Decode 分离（引擎侧大多已具备；完整服务胶水未发布），以及面向 prefill 与 decode 的数据并行负载均衡。Prefill 与 Decode 仍是同一 DeepInfer 引擎的两个阶段，不是两个产品。目标场景强调高吞吐低延迟，但完整在线栈需自备缺口组件。

对比 vLLM / SGLang / TensorRT-LLM？

致谢：DeepInfer 主要基于 vLLM，并参考 SGLang 与 TensorRT-LLM。若要在 SM100 / 昇腾 950 上跑 DeepSeek V4.1-Flash 离线路径，见 对比页。

硬件与安装？

NVIDIA SM100（CUDA 13）与华为 昇腾 950（CANN 9.2）；设置 DEEPINFER_ACCELERATOR。见 硬件、DeepInfer 安装。

与医疗站 deepinfer.org？

无关。标题使用 «DeepSeek DeepInfer»；规范域名为 deepinfer.run。

许可证？

DeepInfer Apache-2.0 · deepseek-recipe MIT。
